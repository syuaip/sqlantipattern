Top 3 Risks

  1. Dynamic SQL + cursor + per-iteration scans (bad-query-samples.sql) — a Critical performance/security cluster: an RBAR cursor wrapping a SELECT * dynamic string, with non-SARGable predicates re-run every loop.
  2. Pervasive over-use of NVARCHAR across every table in Schema.sql — doubles storage on ASCII-only columns (email, phone, codes, status).
  3. Hidden business logic in triggers plus a nullable self-referencing FK — maintainability and referential-integrity risks.

4. Remediation Plan  (Severity × Effort)

P1 — Quick winsS–M · 0.5–2d

C1 UDF-in-predicate, C7 NOT IN, C31 leading wildcard, C2 SELECT * (L5/L707), sp_ rename, DELETE-without-WHERE guard. High ROI, low risk.

P2 — Structural performanceM · 1–2d

B6/B7 add missing FK/search indexes; author the commented-out IX_ProductReviews_ProductID (L685).

P3 — Rewrite RBARM–L · 2–3d

C41 cursor + C32 WHILE → set-based; fix the invalid cursor body (L11–13).

P4 — Schema hardeningM–L · 2–4d

B13 FK NOT NULL; B4 document nullable self-FK; A2 NVARCHAR→VARCHAR sweep (migration); B8/I2 triggers → procedures + multi-row fix; B17 narrow heavy view.

P5 — PolishS · <0.5d

A3 single BIT, random-order seed queries, view filtering docs.

Total: ~6.5–11 man-days. Sprint 1 = P1 + P2 (safe, high ROI); Sprint 2 = P3 + P4 (needs testing / migration window); P5 opportunistic.
